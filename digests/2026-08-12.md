## Full-paper Research Readout

### StreamFlow: Dynamic Memory Flows for Streaming Video Understanding

#### 先说人话

视频持续到来时，模型不能把所有帧永远塞进上下文。StreamFlow 做了三层节流：先在送进视觉编码器前删掉变化小的 patch；把最近 32 帧保留得细一些，把更早历史压成最多 96 个 GOP 记忆槽；回答过程中如果当前 token 对视觉内容的 attention 太低，就取回 4 段历史并压成 32 个 latent token 插回来。

#### FACT — 它到底怎么做

- 输入是 1 FPS 到达的 streaming video 和延迟揭示的问题；问题只在对应时间段结束后出现，模型不能看未来帧。
- 回答骨干是冻结的 Qwen3.5-9B；另用一份 Qwen3.5-9B 加 rank-16 LoRA 做 memory compressor；Qwen3.5-27B 负责生成 evidence + answer 训练标签。
- 每 4 帧组成一个 GOP：第一帧完整保留，后 3 帧只保留相对第一帧 RGB residual 最大的 50% patch。
- 最近 32 帧进入中期记忆；更早内容进入最多 96 个 GOP 槽的长期记忆，满后合并最相似的相邻 GOP。
- VAS 是生成 token 对可访问视觉 token 的跨层、跨头平均 attention mass；低于 0.10 时触发检索。每次取 4 个 GOP、压成 32 个 latent，最多触发 5 次，间隔至少 8 个 decoding steps。

#### FACT — 数据、预算和结果

- Compressor 训练使用 COIN、NeXT-QA、STAR、CLEVRER 官方训练划分及筛选后的 LLaVA-Video-178K；论文没有报告最终样本数、epoch、batch size 或训练时长。训练硬件是 4 张 NVIDIA L20X。
- StreamingBench 含 900 个视频、4,500 个 QA、18 类任务；StreamFlow 得 67.73。Headline 相对 LiveVLM-7B 高 4.63pp，但这是 9B 对 7B、且帧率不同。
- 更可信的同骨干 Qwen3.5-9B 控制中：vanilla 63.26、StreamingTOM 66.56、StreamFlow 67.73；所以 memory policy 的优势是 **+1.17pp**，不是 +4.63pp。
- VideoMME 为 900 个视频、2,700 道多选题、约 254 小时；StreamFlow 为 73.52，相对同骨干 ReKV 的 71.89 高 1.63pp。去掉长期记忆后，long split 从 62.11 降到 51.67。
- 在 RTVU 完整链路统计中，延迟从 7.36s 降到 3.65s，峰值显存从 13.68 GiB 降到 10.80 GiB。统计包含 compressor、retrieval、VAS 和插入后的前向，但不含磁盘解码、模型加载、编译、真实帧到达和等待 GOP 的时间。

#### INFERENCE — 去掉包装后，我们怎么看

- **它主要是系统/工程贡献，不是一个全新的 memory 算法。** 差分 token filtering、层级记忆、相似历史合并、历史检索和 learned-query compressor 都有近邻；新意在于把三段成本控制串成可测的 streaming 闭环。
- **VAS 不是主要增益。** VAS-guided 得 81.55，只比相同预算的 delimiter/random 插入高 0.23/0.49pp；完全不插入才下降 1.37pp。更像是“记忆可访问很重要”，而不是“这个 attention router 很聪明”。
- **反事实证据支持 memory 有用，但不充分支持 VAS。** matched memory 相对 shuffled memory 使正确答案 log-odds 平均增加 0.27；VAS 变化与 grounding gain 的 Spearman 相关仅 0.24。
- **隐藏成本不能忽略。** 部署上多了一份 9B compressor；每个 decoding token 都计算 VAS；27B teacher 与五源数据混合的规模未披露。
- **最明显的机制盲区是静态语义。** RGB residual 容易保留运动、相机抖动和亮度变化，却可能删掉静态文字、物体属性等真正与答案相关的证据。

#### IDEA — 可以缝合成什么

1. **Counterfactual Retrieval Router**：用 matched / shuffled / empty memory 的答案 log-odds 差，监督一个 value-of-information router；在同样最多 5 次、共 160 latent-token 的预算下，对比 VAS、entropy、固定间隔和随机触发。若更少检索仍能保分，这是比 attention heuristic 更一般的 memory decision 问题。
2. **Semantic-Residual Dual Memory**：把同样 50% patch budget 拆成动态 residual quota 与 query-semantic quota，专门在静态文字、静态物体状态、相机运动子集上测 evidence recall、RTVU accuracy 与 VFE latency。风险是问题晚到时，被删原始 patch 已无法恢复，需要廉价低分辨率缓存。

#### 最终判断

- 研究类型：算法 3.0 / 工程 4.5 / 评测 4.0。
- 值得复现：先复现 residual patch selection 与 matched-budget memory insertion，不必先复刻完整 VAS。
- 可信边界：系统级效率与长期记忆消融较 solid；“动态视觉依赖感知”叙事明显高于其独立实验证据。
- [Paper](https://arxiv.org/abs/2608.10949) · [PDF](https://arxiv.org/pdf/2608.10949)

## Deep-read Candidates

### 1. Thinking With Tools, Not With Pixels

- **作者声称**：保留 crop/zoom 的工具名、坐标、目标和意图文本，但把返回图像替换为 `[Image output skipped]`，在 LoRA、全参微调和 RL 中仍与完整像素工具持平或更好，同时减少 29–46% 延迟。
- **我们的判断**：这不是“更好的工具 agent”，而是对 agentic visual reasoning 的必要性审计。若结论成立，许多方法的收益来自 spatial scaffold 或训练分布中的调用格式，而不是主动获取的新视觉证据。
- **全文要查**：是否缺少 returned pixels 真正必要的任务；训练 query 是否泄漏；是否匹配 reasoning token 和 spatial-code 预算。
- [Paper](https://arxiv.org/abs/2608.09682) · [PDF](https://arxiv.org/pdf/2608.09682)

### 2. Perception Before Supervision

- **作者声称**：用“zoom-in 改变答案、移除区域却不改变全图行为”等反事实门，找出模型能看见却没利用的 blind spot，再转成 dense contrastive token supervision；Qwen3-VL-8B 在 12 个 benchmark 上均有收益。
- **我们的判断**：它把主动 crop 从推理工具改造成 on-policy 数据选择器，可能是“证据是否 load-bearing”与视觉自蒸馏的有效结合。
- **全文要查**：三门规则是否偏爱 crop-friendly 题型，额外前向预算多大，所谓无 regression 是否有统计支持。
- [Paper](https://arxiv.org/abs/2608.09931) · [PDF](https://arxiv.org/pdf/2608.09931)
